# RKNN Model Converter

Отдельная утилита для сборки RKNN-моделей под Rockchip. Она не импортирует код приложения `multiview-emotion-detector` и не изменяет его конфигурацию.

Сейчас поддерживаются два сценария:

- `smile`: бинарный checkpoint улыбки `.pth`, обученный на базе EmotiEffLib EfficientNet-B0, преобразуется в ONNX и затем RKNN. Пакет включает проверку совпадения PyTorch и ONNX, `manifest.json` и `config-snippet.yaml` для подключения результата в приложение.
- `onnx`: статический ONNX-файл напрямую компилируется в RKNN.

## Требования

- Linux ARM64 или x86_64; Orange Pi 5 Plus подходит.
- Python 3.10.
- RKNN Toolkit2 той версии, которая совместима с Lite/runtime в целевом приложении. На Orange Pi используйте именно ARM64 wheel.
- Для `smile`-сценария нужны пакеты из `requirements.txt`.

Можно использовать уже созданное Python-окружение проекта, если зависимости совместимы. Второе окружение не является обязательным. Проверьте версию Runtime в окружении приложения до установки Toolkit2: системная `librknnrt.so` может отличаться от библиотеки, которую использует приложение.

## Установка зависимостей

Активируйте Python-окружение, в котором будет работать конвертер, затем установите зависимости:

```bash
python -m pip install -r requirements.txt
python -m pip install rknn-toolkit2==2.3.2
```

Замените `2.3.2`, если приложение использует другой совместимый Runtime. Установка Toolkit2 может изменить версии общих библиотек, поэтому при использовании окружения приложения сначала проверьте вывод `pip` и не подтверждайте обновление несовместимых с приложением пакетов.

## Конвертация `.pth` улыбки

```bash
python rknn_converter.py smile \
  --checkpoint /path/to/final_smile_model_improved_2.pth \
  --output-dir /tmp/smile-model-release
```

Папка результата должна быть новой или пустой. В ней будут:

- `final_smile_model_improved_2.onnx`;
- `final_smile_model_improved_2.rknn`;
- `manifest.json` с хэшем checkpoint, платформой, версией Toolkit2 и результатом проверки графа;
- `config-snippet.yaml` с параметрами бинарного выхода.

Конвертация начинается с FP16 без INT8-калибровки, чтобы не вносить необмеренное ухудшение recall.

## Конвертация статической ONNX-модели

```bash
python rknn_converter.py onnx \
  --input /path/to/model.onnx \
  --output /path/to/model.rknn \
  --target-platform rk3588
```

## Подключение модели улыбки

Скопируйте полученный `.rknn` в `models/smile_prediction/` приложения. Объедините значения из `config-snippet.yaml` с существующим разделом `MODELS` приложения. Скрипт только создаёт файлы конвертации; он не меняет приложение и не перезапускает его.

Проверка в конвертере сравнивает выход PyTorch с ONNX на случайных нормализованных входах. Она не подтверждает качество распознавания на лицах и не заменяет тест на Orange Pi. До съёмки измерьте recall на размеченных кропах и FPS приложения на записи сетки камер.
